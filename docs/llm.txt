# Spec Kit Developer Guide

> A friendly, hands-on guide to Spec-Driven Development (SDD) with GitHub Spec Kit. It goes from simple to complex: two small onboarding exercises (L0 on python-slugify, L1 a tiny split_bill app), then one real multi-feature project, the Invoice Exception Desk, from L3 on. The work is split three ways: a human or strong model writes the constitution, spec, plan, and answer key; a free model (OpenCode with opencode/deepseek-v4.1-flash-free) runs tasks and implement; and a separate reviewer grades the result against a hidden answer key.

The guide is written while learning, so it records the confusing points too. The audience is practicing senior engineers who already use AI coding agents, with full step-by-step help for mid-level developers. Results come from real free-model runs, graded only against the reviewer's answer keys and the projects' own tests. They are not independently certified beyond that. Lessons L1 to L4 were recorded and checked on specify-cli 1.1.3 and OpenCode 1.19.3; L4.5 upgrades l3h-handoff to specify-cli 1.2.3, and older lesson branches stay pinned to 1.1.3. OpenCode v2 reportedly removed opencode run --command (github/spec-kit#4639).

## Guide

- [Home](https://tosin2013.github.io/invoice-exception-desk/): Should this work use SDD at all (a decision gate), the Spec Kit loop, and a router by project stage
- [L0: Start from an existing repo](https://tosin2013.github.io/invoice-exception-desk/L0-existing-repo.html): Brownfield adoption in six steps on python-slugify, with two example runs (free model plans vs the recommended split), not a controlled experiment
- [L1: Setup](https://tosin2013.github.io/invoice-exception-desk/L1-setup.html): Install specify-cli, run specify init --integration opencode, use the dot-syntax commands (/speckit.tasks), and build a tiny first feature
- [L2: First feature, end to end](https://tosin2013.github.io/invoice-exception-desk/L2-first-feature.html): Take split_weighted through specify, clarify, plan, tasks, implement, and analyze, graded by a hidden 169-check answer key
- [L3: Invoice Exception Desk walkthrough](https://tosin2013.github.io/invoice-exception-desk/L3-invoice-desk.html): First slice of roadmap phase R1 (import, rejection reasons, cent totals, aging for AT-01 to AT-04), with analyze before implement and a sealed answer key that caught a paid-invoice bug 119 green tests missed
- [L3.5: Handing work between coding agents](https://tosin2013.github.io/invoice-exception-desk/L35-agent-handoff.html): AT-05 (deterministic follow-up queue, owners and notes) built across a real two-agent handoff: OpenCode on a free model wrote spec, plan and tasks and T008-T024; a fresh OpenAI agent did T001-T007 from a frozen packet; review found bugs 168 green tests missed; no sealed key for AT-05 yet
- [L4: Changing a spec after code exists](https://tosin2013.github.io/invoice-exception-desk/L4-maintenance.html): FR-008 superseded by FR-008a (only positive canonical amounts; 0, 00, 0100 rejected) under constitution v2.0.0: dated Clarification, tests changed first (8 failed before code, 205 passed after), analyze on 003 and 004 (4 HIGH, all stale text, fixed), drift.md, and a PASS against an L4 answer key sealed by OpenAI/Codex before the build
- [L4.5: Upgrading Spec Kit itself](https://tosin2013.github.io/invoice-exception-desk/L45-speckit-upgrade.html): A repeatable routine for any Spec Kit upgrade (release notes, tag diff of templates and command prompts, throwaway-clone dry run with specify integration upgrade and no --force, verify constitution and specs unchanged, own branch and PR, doc pins), with 1.1.3 to 1.2.3 as the worked example: templates identical, 6 managed files changed, 205 tests still passing, one analyze smoke run
- [L5: Letting an agent loop run unattended](https://tosin2013.github.io/invoice-exception-desk/L5-agent-loop.html): FR-007 superseded by FR-007a (a due date must not be before the issue date; equal dates valid; reuses invalid_date), built by OpenCode on a free model with the Spec Kit Ralph Loop extension v1.5.0 in a locked-down, keyless container, handed over as a git bundle; run r3 passed every sealed case but failed on scope because uv run created an untracked uv.lock; kit v4 (UV_NO_PROJECT=1, clean-tree check after the baseline) and a fresh seal; run r4 graded PASS (86/86, 38/38, 33/33, 209 tests, 142 of 300 lines), merged by PR #14
- [L6: From an approved issue to a PR you can trust](https://tosin2013.github.io/invoice-exception-desk/L6-issue-to-pr.html): FR-032 (accepted import rows also expose issue_date and due_date as ISO strings and the trimmed currency; closes drift 003-U1) built from GitHub issue #16 as the ruling, with no custodian or sealed key: the issue settles every choice and states the constitution exception, Tosin adds agent-ready, the L5 container runs OpenCode with Ralph from a hash-checked issue snapshot (13 preflight probes, scope stops and flags), and a post-run self-check the builder never sees runs the 6 acceptance checks and the 209 base tests unchanged; 3-minute run, 1 Ralph iteration, 3-line code change, 215 tests, 229 of 300 lines, self-check PASS, reviewed by Grok Bot (APPROVE with nits: stand-in test rows, a wrong self-reported line count), merged by PR #17
- [L7: CI is the grader](https://tosin2013.github.io/invoice-exception-desk/L7-ci-grader.html): The L6 no-custodian flow plus a read-only GitHub Actions workflow (.github/workflows/ci.yml, job tests, no secrets, PR #21) that grades every PR: full suite, acceptance/ tests when present, base test IDs still present, and a diff-size summary; FR-033 (accepted rows expose overdue as a bool, rejected and duplicate rows carry overdue: None) from issue #22, with one approved base-test edit (overdue added to the exact key sets); the builder can't touch .github/ or acceptance/, the acceptance tests stay in the kit until the bundle is sealed, and Spec Kit adds them as a separate grader commit; 3-minute run, 1 Ralph iteration, local self-check PASS, CI green in 9s (223 passed, acceptance 8/8, all 215 base tests present), merged by PR #23 on green CI with the review skipped (a judgment call: CI checks test IDs, not test bodies)
- [L8: Dependabot, graded like everyone else](https://tosin2013.github.io/invoice-exception-desk/L8-dependabot.html): Dependabot version updates with no repo settings changed: alerts and security updates explained but left off on purpose (no runtime deps; security updates only target the default branch); pytest pinned one release behind (pytest==9.1.1 in requirements-dev.txt, CI switched from an unpinned --with pytest to --with-requirements "$GITHUB_WORKSPACE/requirements-dev.txt" because the base-tests step runs in a worktree of the base commit; PR #25 into l5-setup); a three-block .github/dependabot.yml on the default branch (github-actions weekly grouped and pip allow pytest, both with target-branch l5-setup; github-actions monthly grouped for Pages on main, ungraded; PR #26); within a minute Dependabot opened PR #27 (actions/checkout 4 to 7 into l5-setup, graded green by the unchanged L7 CI in 9s, clearing the Node 20 warning) and PR #28 (pages group, 4 updates, into main, ungraded); no pytest PR yet because of the 3-day default cooldown (job log: Filtered out 1 versions due to cooldown); a human merges every Dependabot PR on green, no auto-merge, read-only token and no secrets; five recipes (Actions only, one dev dependency via allow, grouped minor/patch with majors ignored and a PR cap, Docker base image, security-updates-only and the uv ecosystem)
- [PLAYBOOK: the wrap-up](https://tosin2013.github.io/invoice-exception-desk/PLAYBOOK.html): The whole pattern on one page for any AI to apply to its own project (source: https://github.com/tosin2013/invoice-exception-desk/blob/main/PLAYBOOK.md; raw: https://raw.githubusercontent.com/tosin2013/invoice-exception-desk/main/PLAYBOOK.md): constitution, the issue as the ruling, spec/plan/tasks, a Ralph builder run in a keyless sandbox, a separate grader commit with acceptance tests, read-only CI as the grader, a human merge; roles and trust boundaries; a table linking every level; loop tuning (iteration caps, timeouts, empty-output retries, diff cap, scope and clean-tree checks, the post-run self-check, when to stop, retry or rerun); the L8 Dependabot recipe; a numbered checklist for a new project; and known gaps (CI checks base test IDs, not their bodies)
- [Prompts](https://tosin2013.github.io/invoice-exception-desk/PROMPTS.html): Copy-paste prompts, one per situation (new project, existing repo, controller/worker run, harness and model choice, roadmap rows to issues, resuming after a break, moving the roadmap forward), each linking its PLAYBOOK section
- [PLAYBOOK companion: infrastructure repos](https://tosin2013.github.io/invoice-exception-desk/PLAYBOOK-infra.html): Applying the pattern to OpenShift/Kubernetes repos: infra constitution, no cluster credentials for the worker, an evidence ladder beyond static CI, onboard.yml, a repeatability check, and a direct mode without a worker
